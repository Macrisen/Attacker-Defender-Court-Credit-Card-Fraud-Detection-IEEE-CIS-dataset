The previous holdout boundary is preserved exactly: TransactionDT ≤ 12192842 belongs to the pre-holdout period. Sorting is by time then ID; identical timestamps never cross a boundary. Rows labeled “inner”, “calibrator” and “selection” are nested subsets, not additional transactions.

  1. Within the first approximately 65%, use an earlier 85% for inner fitting and the later 15% for early stopping by average precision. Inner encoders are fitted only on inner-fit rows.
  2. Refit the chosen number of trees and final categorical mappings on the entire model-training period. Calibration and holdout are excluded.
  3. Inside the calibration period, fit candidate calibrators on its first half and select the method by log loss on its next quarter (Brier breaks ties).
  4. Refit each calibrator on the first three quarters of calibration. Select the reward-maximizing threshold on the last quarter. Then freeze everything before holdout evaluation.
The prior feature-selection audit used the earliest 80%, including the present calibration period. The final 20% remains untouched by that selection, but calibration-period model-selection estimates are conditional on the preselected feature set and are not a completely independent feature-selection assessment.

2. Model and feature preparation

Primary Defender: experiment B (current clean tables). Numerical NULLs remain missing; there is no imputation, scaling, oversampling, class weighting or outlier deletion. Text fields, card/address codes and id_12–id_38 are categorical under a conservative metadata policy. V/C/D numeric measurements and id_01–id_11 remain numerical; anonymized semantics still require domain review.

Categorical vocabularies are learned only from model-training rows. Missing and unseen categories map to −1 for LightGBM's native missing handling. Numerical predictors use float32 consistently at training and inference; original SQL values are unchanged.

Batch prediction time measures raw LightGBM holdout inference; single-transaction latency includes schema checks, feature encoding and calibration after loading artifacts, using two warm-ups and ten measurements. Peak RSS is the process-wide cumulative high-water mark, not an isolated per-experiment memory delta.

The artifacts/ directory contains the booster, selected calibrator, categorical mappings, feature order/types, threshold policy, training configuration and pinned dependencies. defender.inference provides predict_fraud_probability(transaction) and defender_decision(transaction, threshold=1/6). Explicit NULLs and unseen categories are supported; missing predictor keys or unexpected fields are rejected.

Saved-model predictions were checked against in-memory holdout predictions, including unknown-category and missing-value cases. Detailed execution logs, source hashes, database snapshot identifier and a hash of the extracted training snapshot are retained. Credentials come from libpq environment variables/.pgpass or a local .env, and are never saved in model artifacts.

10. Conclusions and limitations

The cleaned baseline achieved holdout AP 0.4867 and ROC-AUC 0.8713. At the prespecified 1/6 threshold it recovered 49.36% of fraud, incorrectly flagged 2,139 legitimate transactions, and approved 2,058 fraudulent transactions, with mean reward 0.6783.

This is a saved, reproducible offline Defender baseline suitable for integration testing and subsequent research. It is not evidence of robustness against adaptive attackers, production readiness, or optimal investigation allocation. No RL environment, Attacker, Court, continual update loop, delayed labels or counterfactual action outcomes have been modeled.

  • Validation is one chronological holdout; uncertainty intervals and repeated temporal backtests have not been estimated.
  • Calibration and thresholds can drift. Monitor probability quality, recall, false positives and reward over time.
  • Anonymized feature availability at decision time remains unverified. Unknown semantics are not automatically treated as leakage.
  • Numeric-coded categories and missing-as-unknown policy need domain validation. Test labels are unavailable and no test accuracy is claimed.
  • The historical Kaggle test period is later than the labeled period. Schema compatibility does not guarantee performance under that shift.
  • Reward values are research assumptions; no real monetary loss or operational capacity is represented.
